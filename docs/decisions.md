# 설계 결정과 기각된 것

결론만 남기면 다음 세션이 같은 대안을 다시 제안한다. 기각 이유까지 적는다.

## 원칙

- 자동화는 생활 패턴에 심리스하게 스며들어야 한다. 경고창·강제 제한·다단계 인터랙션 거부
- 제약이 있으면 기능을 포기하지 않고 **능동적으로 회피**한다
- **확장 미사용자도 혜택을 받아야 한다** (SEAF-1 방향을 정하는 제약)

## 결정

| 주제 | 결론 | 기각된 대안과 이유 |
|---|---|---|
| IP 밴 | 다른 도구의 주기를 피하거나 그 주기엔 fetch 생략 (미해결, SEAF-2) | 최소 주기 강제·경고 UI — 제약을 사용자에게 떠넘김 |
| 본문 버튼 | 조회 페이지 `convertLobbyLinks`로 버튼화 | 에디터 안 인라인 스타일 버튼 — 디시 저장 시 href·스타일 제거 (사용자 판정 "실패") |
| 배포 | zip 압축해제 로드 → 웹스토어(1.0.0) | CRX 직배포 — Chrome이 스토어 외부 CRX 설치 차단. CRX는 스토어·정책 배포용 포맷 |
| 서명 키 | PEM 하나를 전 버전 재사용, gitignore, 안전 보관. 메타데이터는 `signing-metadata.json` 분리 | 평문 메타데이터 base64를 PEM으로 — 인코딩은 암호화가 아니고 PEM은 Chrome이 만드는 개인키 |
| 제목 필터링 | 보류. 로비 링크 있으면 무조건 알림 | `detectCategory`/`detectDifficulty`/`checkFilterMatch` — bg에서 `SEAF_TAGS` 미정의 오류 |
| 제목 자동완성 | 태그 변경 시 입력칸 전체 덮어쓰기 | 사용자 입력 보존 — 복잡도 대비 가치 낮음 |
| popup/settings 높이 | 통일 시도 후 롤백 | — |
